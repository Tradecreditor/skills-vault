## 方法 (notes / caveats)

- **Window/WEEK resolution — read this first**: `routines/weekly-hot-list.md`'s cron is `0 1 * * 1` UTC
  (Monday 01:00 UTC). This run actually executed 2026-09-22T01:09 UTC (Tuesday) — about 24h after that
  scheduled Monday firing. The vault's *first* hot-list run (`2026-W38`) was itself an ad-hoc/manual run on
  Sunday 2026-09-20 evening (before the vault's first real Monday cron would have fired), covering window
  2026-09-14..20. Taking this run's nominal "today" as the intended Monday (2026-09-21, per the routine
  prompt's "Today is Monday" framing and matching `outputs/health/2026-W39.md`'s own W39 labelling from that
  same Monday), the previous-Monday-to-Sunday window resolves to **2026-09-15..21** and `WEEK = 2026-W39`.
  This is one calendar day later than a "clean" ISO week 39 (which would be Sep 21–27) because the vault's
  actual history compressed two nominal weekly cycles into 4 real days (vault init 09-18 → first run 09-20 →
  this run 09-22). Net effect: this window overlaps 2026-09-15..20 with `2026-W38`'s already-reported
  2026-09-14..20 — candidates from that overlap were re-examined fresh (their numbers may have grown since
  last week's capture) rather than skipped, and the dedupe check below confirms none of this week's winners
  were already in the vault.
- **GitHub**: 10 per-topic searches (`created:>=2026-06-17 stars:>=1000`, sorted by stars, 30/topic) + 1
  breakout search (`created:>=2026-09-15 stars:>=1000`, 50 results), all via
