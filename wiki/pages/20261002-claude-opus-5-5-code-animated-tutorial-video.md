## 摘要
數位敘事力期刊主編覺得網上好多 Opus 5.5 程式碼動畫只見成品、唔講底層邏輯，於是請 Claude Opus 5.5 自己做咗一部約 7 分 48 秒嘅教學片；旁白（ASR 轉錄）一開場就話成條片冇打開過任何剪輯軟件，畫面、字幕以至聲音全部由程式碼產生。旁白講明：要由零做成套動畫（規劃分鏡、管理多個場景、自己檢查畫面）就揀 Opus 5.5，日常微調用 Sonnet，批量改字幕之類細工用 Haiku 4.5；原理係語言模型唔畫圖、只寫「時間 → 畫面」嘅描述（宣告式動畫，用 HTML／CSS／GSAP、Remotion 或 Manim），瀏覽器逐格渲染截圖，再由 FFmpeg 合成影片。穩定做法係先出 JSON 分鏡表（每幕寫旁白、畫面想表達乜、秒數、同上一幕點接），再用八個參數嘅提示詞框架，最後靠「寫碼、渲染預覽、截圖、Claude Code 自己睇圖修正、再跑」嘅迴圈把關品質，所以驗收標準要寫入提示詞。聲音方面，旁白建議用識理解語氣嘅語音模型，加標點同停頓控制斷句同情緒提示，再用 Whisper 攞逐字時間戳，令字幕同動畫貼住旁白。成本資料只見於 caption、旁白冇講：作者話免費基本上做唔到，呢部片用咗佢一週約 4% 用量，另加 Hyperframes skill 同 Eleven Labs 語音（月度免費額度用咗一半）；佢嘅提示詞鷹架喺留言區，今次未攞到。

- Opening claim (narration): the video was made without opening any editing software; every frame, every subtitle line and even the voice you hear are generated by code. The video then takes the production line apart from start to end.
- Model choice (narration): Opus 5.5 is the main model for building a whole tutorial animation from scratch, because the job needs storyboard planning, handling many scenes at once and checking the picture itself ("good at long, multi-step, complex tasks"). Sonnet ("fast and cheap", ASR reads "S on et 5" so the version is unclear) is for everyday tweaks such as changing a colour or adjusting a transition. Haiku 4.5 is "enough" for small batch jobs such as batch-editing subtitles or replacing 100 words (ASR "单名", garbled). Rule of thumb: the more complex the animation and the more iteration steps, the bigger the model.
- Why a language model can animate (narration): it does not draw; it writes a description. A video is many images played fast (30 per second) and each frame depends on one thing, the current time, so the video can be written as a function: give it the time, it returns that frame. This is called declarative animation: describe in HTML + CSS + GSAP, or React Remotion, or Manim (math animation; ASR "Man ning") what moves where at which second. The browser renders each frame, the program screenshots frame by frame, and FFmpeg (ASR "FF M MP G") stitches the frames into a video. Writing text descriptions is what language models are best at.
- Storyboard first (narration): asking Claude (ASR "Cloud") "make me an animation" gives a different result each time. The steadier way is to have it produce a storyboard as structured JSON (ASR "Jason") where each scene states four things: what the narration says, what the picture should express, how many seconds it runs, and how it connects to the previous scene. Visuals, voice-over and subtitles then all follow the same data instead of each doing their own thing.
- Prompt framework with eight parameters (narration; contrasted on screen with the one-liner "make me an animation introducing AI"): (1) role and audience, because who the video is for sets tone and voice; (2) output spec, frames per second and total length pinned down so no odd sizes appear; (3) design system, palette, typeface and style for consistency; (4) storyboard JSON, the blueprint above; (5) animation and motion, which easing curves, how to transition, fast or slow pacing, "this decides the feel"; (6) technical constraints, name the engine and forbid random numbers and real-time clock so every render is identical; (7) asset rules, where assets come from, what licence, how large screenshots should be; (8) acceptance criteria, require it to screenshot itself and check for text overflowing its box, misalignment and Chinese characters turning into tofu squares.
- Wording tip (narration): numbers beat adjectives; instead of "make the animation smoother" say "0.6 s ease-out".
- Output loop (narration): Claude Code writes the code, renders a preview, takes a screenshot, then looks at the image itself, notices for example that text overflows a box or two elements are not aligned, fixes it and runs again. This is why acceptance criteria go into the prompt: give it a standard it can see and it can reach it. The caption calls this the "automated check" step of the output loop.
- Voice (narration): text-to-speech is text to prosody to sound, and the robotic feel is mostly flat prosody (no pitch movement, no pauses or breaths), not the timbre. Three fixes: choose a model that understands tone (the video used ElevenLabs, which the ASR garbles as "E le ven L apse"; the caption confirms Eleven Labs), control phrasing with punctuation and pause marks, and add emotion cues (question, emphasis, light touch).
- Audio-visual sync (narration): Whisper (ASR "Wh is per") is not for dubbing but a speech-to-text transcriber; here it finds the millisecond at which each word is spoken. With those word timestamps, subtitles follow the voice word by word and an on-screen animation can appear exactly when a keyword is said.
- Recap (narration): pick the right model, write the prompt with the eight parameters, produce the storyboard first, generate visuals and self-correct, add voice, align subtitles, render.
